# 任务 1 ★：重置【自定义钓竿的穿刺技能】

## 这是什么

高级钓竿有种配件叫**直钩**，装上以后小人获得「**穿刺**」技能：
向前方一条线捅出去，打中所有敌人。

**现在能跑，但效果/手感要重做。**

## 相关文件

| 文件 | 作用 |
|---|---|
| `Source/Binguin/Ability_BinguinRodSkills.cs` | **效果本体** —— `CompAbilityEffect_BinguinPierce` |
| `AdvancedFishing/Defs/Feature/Rods/Fishing_RodsAndParts.xml` | `Binguin_AbilityPierce` 的 def（技能名、冷却、描述）+ 鱼钩 def |
| `Source/Binguin/BinguinDefPatches.cs`（约 L1483 起） | 把 `Binguin_AbilityPierce` 挂到成品直钩竿上 |

## 当前设计

`AdvancedFishing2_Binguin.xml` 里 description 的原文：

> 直钩：获得技能「穿刺」——对前方 **10 格**内所有敌人造成 **200% 于武器面板**的伤害，**冷却 10 秒**。

`Ability_BinguinRodSkills.cs` 里的实现要点：

| 项 | 现状 |
|---|---|
| 方向 | `目标格 - 自己位置` 归一化，取整成 `IntVec3` |
| 伤害类型 | `Stab`，找不到就退回 `Cut` |
| 伤害乘数 | `pawn.GetStatValue(DamageMultStat)` —— ★ 在循环外**只取一次**（性能） |
| 目标筛选 | 不打自己 / 友军 / 盟友 + `GenSight.LineOfSight`（不隔墙） |
| 特效 | 脚下尘土 + 直线路径冰屑拖尾 |

## ★★ 必须保留的 3 个实现要点（别改掉）

### ① 必须走 Ability 系统，**不能**用 `ThingDef.verbs`

给 `verbs` 挂东西会让武器被判定成**远程武器** —— 早期踩过这个坑
（用户反馈原话：「鱼竿变远程武器」）。

**正确路线**：

```
装备武器 → CompBinguinRod.Notify_Equipped → pawn.abilities.GainAbility
        → AbilityTracker.GetGizmos 自动显示能力按钮（近战武器判定完全不受影响）
```

### ② `Valid` / `CanApplyOn` 必须 `override` 返回 `true`

```csharp
// ★ 基类对特定子类型做硬 cast，不 override 会 InvalidCastException
//   表现：日志里刷 "Root level exception in OnGUI"
public override bool Valid(LocalTargetInfo target, bool throwMessages) { return true; }
public override bool CanApplyOn(LocalTargetInfo target, LocalTargetInfo dest) { return true; }
```

目标合法性交给 `verbProperties.targetParams` 去限制。

### ③ 伤害要走 `StatDefOf.MeleeDamageFactor`

技能等级 / 特质加成必须正常生效，别写死伤害。

## 重置方向（待作者确认最终规格）

- [ ] 是"**穿透多个目标**"还是"**前方一条线全中**"？

# 任务 2 ★：重置【制作钓竿的 UI】

## 这是什么

钓竿装配台的界面。**现在有两套入口并存**，需要整合重做。

## 现状：两条入口

都从装配台的 **gizmo 按钮**进（`Source/Binguin/Comp_BinguinRodAssembly.cs` 的 `CompGetGizmosExtra`，约 L252-321）：

| 按钮 | 实现 | 交互 |
|---|---|---|
| 「装配钓竿」 | `Source/Binguin/RodPartPicker_Binguin.cs` | **地图点选 4 次**：打开后依次点 竿身→竿头→鱼钩→鱼饵，每步只高亮该类物品 |
| 「从库存选配件」 | `Source/Binguin/Dialog_BinguinRodStockPick.cs`<br>+ `Source/Binguin/RodPartStock_Binguin.cs` | **一个窗口**：4 个槽位，每槽「更换」→ 弹出该类候选列表；下面一排按钮选殖民者；底部「开始装配」 |

## 保留但当前**没接上**的对话框（可当参考）

| 文件 | 说明 |
|---|---|
| `Source/Binguin/Dialog_BinguinRodAssembly.cs` | 按**材质**精确列出 4 类配件 + 选制作人 + 属性预览（现在被注释掉了） |
| `Source/Binguin/Dialog_BinguinRodWorkerPick.cs` | 第 5 步「选谁来装配」 |
| `Source/Binguin/Dialog_BinguinResumeRodAssembly.cs` | 半成品「继续装配」选人 |
| `Source/Binguin/Dialog_BinguinBait.cs` | 制作鱼饵（选 1~2 种食材效果） |

## ★★ 改之前必须知道的坑

### ① 不要用 `Find.Targeter.BeginTargeting` 链式弹下一个 targeter

`Targeter.StopTargeting()` 的 IL 是**先调回调、再清字段** ——
你在 `actionWhenFinished` 里刚设好的 `targetParams` / `action` / `targetValidator`
会被**立刻清空** ⇒ 表现是"没有圆圈、点不了"。

另外两个重载也不行：

| 重载 | 问题 |
|---|---|
| 6 参数 | **不接受** validator 参数 |
| 5 参数 | IL 里直接把 `Targeter.targetValidator` 置成 `null`；而 `ProcessInputEvents` 在 `targetingSource == null` 时判的**正是这个字段**（不是 `targetParams.validator`） |

> 完整踩坑记录写在 `RodPartPicker_Binguin.cs` 文件头，改之前**先读那段注释**。

### ② "选人"这一步用**窗口**，不要用地图点选

同上原因（`Dialog_BinguinRodWorkerPick.cs` 文件头也写了）。

### ③ 配件分类规则在**两处重复**，改一处要改两处

| 位置 | 类 |
|---|---|
| `RodPartPicker_Binguin.cs` | `Steps` |
| `RodPartStock_Binguin.cs` | 分类列表 |

**顺序固定**：竿身 → 竿头 → 鱼钩 → 鱼饵

```
竿身：Binguin_RodShaft_Long / Binguin_RodShaft_Short
竿头：Binguin_RodTip_Blade  / Binguin_RodTip_Hammer
鱼钩：Binguin_RodHook_Straight / Binguin_RodHook_Curved
鱼饵：Binguin_RodBait（只有一种）
```

**扫描范围**：整个地图的 `ThingRequestGroup.HaulableEver`
（不做储存区/距离过滤 —— 用户明确要求"散落在外面地上的也能选"）

> 💡 重构时建议把这两处合并成一个共用类，顺手把这个隐患去掉。

### ④ 半成品的续接逻辑在 `Comp_BinguinUnfinishedRod.cs`（34 KB，最复杂）

里面有 `stallTicks` 看门狗（`StallResetTicks = 600`）。
**改装配流程前先读这个文件的注释。**

### ⑤ ★ 注意：`Comp_BinguinRodAssembly.FinishAssembly()` 是死代码

全代码库里**没有任何调用点**（已核实）。真实收尾逻辑在 `Comp_BinguinUnfinishedRod.cs`。
**别照它理解现在的流程。**
