### 2.3 ⚠️ 音效与音符都被 DLC 门槛卡住

`Source/RimWorld/Building_MusicalInstrument.cs`：

```csharp
public void StartPlaying(Pawn player)      // ★ 非 virtual，不能重写
{
    if (ModLister.CheckRoyaltyOrIdeology("Musical instrument"))   // ← 门槛
        currentPlayer = player;
}
private Pawn currentPlayer;                // ★ private，音符 fleck 依赖它
protected override void Tick()             // ★ protected override，可以重写
{
    base.Tick();
    if (currentPlayer != null) { 启动 soundPlaying } else { soundPlaying = null; }
    soundPlaying?.Maintain();
}
```

我们的音效字段：**5 件全是** `<soundPlayInstrument MayRequire="Ludeon.RimWorld.Royalty">Harp_Play</soundPlayInstrument>`
⇒ 没装 Royalty 时该字段为空 ⇒ 也没声音。

**⇒ 自办演唱会要"有声音 + 有音符"，必须自己维护播放状态**（见 6.3）。

## 3. 目标体验（玩家视角）

```
① 在殖民地建一组合格乐器（≥1 麦克风 + ≥2 件其它乐器）
       ↓
② 点乐器 → gizmo「举办演唱会」
       ↓
③ 像文化仪式那样弹出选人窗口：
     左：候选殖民者（带 Artistic 技能、状态、不适合的原因）
     右：角色槽位 —— 主唱 / 键盘 / 鼓 / 吉他 / 贝斯 / 观众
     下：曲目选择（歌曲库）
       ↓
④ 确认 → 可选「邀请外派系观众」（发邀请信 → 对方决定来不来）
       ↓
⑤ 开演：
     · 乐手走到各自乐器操作点演奏
     · 主唱到麦克风
     · 我方观众入座/站位观看
     · 外族观众进场、就座
     · 音符 fleck + 演奏音效（自己维护）
     · 全场持续加 Recreation
       ↓
⑥ 4 小时后自动收尾（或手动停 / 主唱倒下）：
     · 按 Artistic 技能算质量 → 四档
     · 观众（含外族）按票价付钱 → 殖民地收到银
     · 到场者按在场时长获得心情
     · 散场；外族客人离开
```

### 4.4 歌曲库设计（数据层）

**做法**：每首歌一个 `Def`，继承自定义的 `Binguin_SongDef : Def`，在 XML 里声明类型（**新规范允许**）。

```xml

<Binguin.Feature.Band.Binguin_SongDef>
  <defName>Binguin_Song_FrostMoon</defName>
  <label>霜月</label>
  <description>冰鹅族最古老的摇篮曲。</description>
  <style>抒情</style>
  <durationTicks>10000</durationTicks>
  <moodOffset>6</moodOffset>                        <!-- 观众心情加成 -->
  <requiredArtisticLevel>4</requiredArtisticLevel>  <!-- 最低艺术技能 -->
```

- **音频留占位**（`soundDef` 先指向原版 `Harp_Play`），将来拿到 `.ogg` 再补

## 5. 场地判定（要求：必须先建好场地）

### 5.1 什么叫"一组乐器"

照抄 `GatheringWorker_Concert.TryFindGatherSpot`：

```
遍历 map.listerBuildings.AllBuildingsColonistOfClass<Building_MusicalInstrument>()
  → 过滤：ValidateGatheringSpot(InteractionCell ...) && InstrumentAccessible(...)
  → 按 instrumentRange 取最大的一组
```

**我们额外做**：原版只取**一个** spot；我们要把**同一组的所有乐器**都收进来当"乐手位"。
判"同一组"：距离 < range **且同一个 `Room`**。

### 5.2 合格标准

| 条件 | 说明 |
|---|---|
| ≥1 个**麦克风** | `Binguin_Band_Microphone`，主唱位 |
| ≥2 件**其它乐器** | 键盘/鼓/吉他/贝斯任选 |
| 主唱位 + 乐手位**可达** | |
| 圈内有座位（**可选**） | 没座位退化成"站着看"（现有 `JobDriver_BinguinWatchConcert` 支持） |
| 不在演出中 | `!BinguinConcert.Active` |

### 5.3 场地信息预览

乐器上挂 gizmo「查看场地」，显示：几件乐器、都是什么、能坐多少人、缺什么（红字）。

## 6. 发起流程（"像文化仪式"）

### 6.1 入口：乐器上的 gizmo

```csharp
public override IEnumerable<Gizmo> GetGizmos()
{
    foreach (var g in base.GetGizmos()) yield return g;

    if (!ModsConfig.IdeologyActive) yield break;   // ★ 硬检查，没装就不显示
    if (Faction.OfPlayer == null) yield break;

    var venue = BinguinConcertVenue.FindFor(this);
    var gizmo = new Command_Action {
        defaultLabel = "举办演唱会",
        defaultDesc  = venue != null ? "在这个场地办一场演唱会。" : "场地不合格：" + ...,
        action = () => BinguinConcertSetupDialog.Open(venue),
    };
    if (venue == null) gizmo.Disable("场地不合格");
    yield return gizmo;
}
```

**实现方式**：新建 `Building_BinguinBandInstrument : Building_MusicalInstrument` 子类，
XML 里把 `thingClass` 改指它（新规范允许直接写）。
⇒ 一举两得：既能挂 gizmo，又能**自己维护播放状态**（见 6.3）。

### 6.2 选人窗口（`Dialog_BeginRitual`）

```csharp
// 照 Command_BestowerCeremony.cs:65 的用法（ritual / obligation 传 null）
Find.WindowStack.Add(new Dialog_BeginRitual(
    "举办演唱会",              // ritualLabel
    null,                      // Precept_Ritual —— 传 null（授勋典礼就这么用）
    venue.center.ToTargetInfo(venue.map),
    venue.map,
    delegate(RitualRoleAssignments assignments) { StartConcert(venue, assignments); return true; },
    organizer,                 // 主唱
    null                       // RitualObligation —— 传 null
));
```

**角色定义**（`RitualRole` 子类）：
| 角色 | maxCount | required | 说明 |
|---|---|---|---|
主唱 | 1 | ✅ | 必须 |
键盘/鼓/吉他/贝斯 | 各 1 | ❌ | 可缺（缺了对应乐器不演奏） |
观众 | 0~N | ❌ | 默认全选我方殖民者 |
外族贵宾 | 0~N | ❌ | ★ 门票来源 |

### 6.3 音效与音符（绕开 DLC 门槛）

```csharp
public class Building_BinguinBandInstrument : Building_MusicalInstrument
{
    private Pawn _player;
    private Sustainer _sound;

    public void BinguinStartPlaying(Pawn p) { _player = p; }
    public void BinguinStopPlaying() { _player = null; _sound = null; }
    public bool BinguinIsPlaying => _player != null;

    protected override void Tick()
    {
        base.Tick();
        if (_player == null) { _sound = null; return; }
        if (def.soundPlayInstrument != null && _sound == null)
            _sound = def.soundPlayInstrument.TrySpawnSustainer(
                SoundInfo.InMap(new TargetInfo(Position, Map), MaintenanceType.PerTick));
        _sound?.Maintain();
    }

    public override void ExposeData()
    {
        base.ExposeData();
        Scribe_References.Look(ref _player, "binguinBandPlayer");
    }
}
```

- **音符 fleck**：原版靠 `CompProperties_ThrownFleckEmitter` + private `currentPlayer`
  ⇒ 我们自己的状态**触发不了它**，需要**自己在 `Tick()` 里抛 `FleckDefOf.Music`**
  （施工第一步：查 `FleckMaker` 抛 `Music` fleck 的正确 API）
- **音效**：`def.soundPlayInstrument` 现在全是 `MayRequire=Royalty` 的 `Harp_Play`
  ⇒ 建议改成不依赖 Royalty 的音效

### 6.4 预演彩排

开演前让乐手先去站位：复用现成的 `Binguin_BandWaitAtMic`（"站在操作点等 `Active` 变 true"）。

## 8. 演出流程

### 8.1 开始

```csharp
BinguinConcert.Start(venue, singer, musicians, audience, song);
  ├─ EndTick = 现在 + song.durationTicks
  ├─ 派 job：主唱/乐手 → Binguin_PlayInBand；观众 → Binguin_WatchConcert
  ├─ 自己维护每个乐器的播放状态（6.3）
  ├─ 门票结算（BinguinBandTicket.SettleAtStart）
  └─ 弹消息
```

**为什么不用 `LordMaker` 管乐手**：我们的行为是**明确指派 person→instrument**，用 job 更直接可控。

### 8.2 演出中（每 60 tick 检查一次）

| 检查 | 处理 |
|---|---|
| 主唱 null / 死 / 未 spawned / 离场地 | **终止演出** |
| 某乐手失效 | 该乐器停奏，其余继续 |
| 乐器被拆/被毁 | 该乐器停奏 + 消息 |
| 观众走了 | 一期不处理 |
| 有人被征召 | 一期不特殊处理（自己中断 job） |
| 到 `EndTick` | **正常收尾** |

### 8.3 收尾

```
① 按 Artistic 算质量 → 四档
② 只给【到场的】观众发心情（按在场时长定 moodPowerFactor）
③ 表演者心情
④ 停所有乐器播放状态
⑤ BinguinConcert.Stop()
⑥ 外族观众离开（SendEveryoneAway）
⑦ 弹消息（含质量评价）
```

**提前终止三种**：玩家手动停 / 主唱失效 / 所有乐器都没了

## 9. 表演质量（`Artistic` 技能）

```
每位表演者按 Artistic 等级算分：
  主唱 ×1.5（唱歌是核心）
  乐手 ×1.0
平均分 → 四档：
  < 4   → Terrible（惨不忍睹）
  4~7   → Boring（平平无奇）
  8~14  → Fun（很精彩）
  ≥ 15  → Unforgettable（难以忘怀）
```

- 新增 4 个 ThoughtDef（明确四档文本，反馈更清楚）
- `moodPowerFactor` 按"在场时长 / 总时长"（照抄 `LordJob_Joinable_Party.ApplyOutcome`）
- **只给到场的人**（现在 `EndConcert` 是给 `FreeColonistsSpawned` 全部，必须改）
- 娱乐值：照抄 `LordToil_Party.LordToilTick()`，`GainJoy(joyPerTick, JoyKindDefOf.Social)`
  默认 `joyPerTick = 3.5E-05f`（**用原版默认值，不擅自改数值**）

## 13. 施工顺序

1. **先核实 3 个 API**（免得写完才发现签名不对）：
   - `Dialog_BeginRitual` 的 `RitualRoleAssignments` 怎么读"某角色分到了谁"
   - `FleckMaker` 抛 `Music` fleck 的正确 API
   - `Building_MusicalInstrument` 的 `InteractionCell` / `instrumentRange` 取法
2. 然后按 4.1 的顺序写：场地 → 乐器子类 → 歌曲库 → 导演 → 角色 → 对话框 → 质量 → gizmo → 门票衔接 → 调试
3. 每完成一块编译一次（从仓库根：`dotnet build Source/Binguin/Binguin.Race.sln -c Release`）
4. `git` **不推**（作者指令）

### 验收标准（每条都要实测，不能只看"编译过了"）

1. 建好合格场地 → 乐器上出现「举办演唱会」按钮
2. 场地不合格 → 按钮灰掉，说明缺什么
3. 没装 Ideology → 按钮不出现，日志无红字
4. 点按钮 → 弹出**像文化仪式**的选人窗口，能选主唱/乐手/观众
5. 能选曲目
6. 开演 → 乐手就位、主唱到麦克风、观众入座
7. 演出中 → **有音符、有声音**、观众娱乐值上升
8. 邀请外派系 → 对方来 → 到现场观看
9. **门票收入正确**（按票价 × 人数 × 场地评分）
10. 4 小时后自动收尾；**只给到场的人**发心情
11. 主唱中途死亡 → 演出中断、有提示、状态清干净
12. 中途存档读档 → 状态正确恢复或正确取消
13. 与"乐队来访"不冲突
14. 全程 `Player.log` **无红字**
