### 1.4 乐器天生就是原版乐器（★★ 最重要的发现）

`Defs/Feature/Band/BandVisit_Binguin.xml` 里 5 件乐器：

```xml
<ThingDef ParentName="MusicalInstrumentBase">
  <defName>Binguin_Band_Keyboard</defName>
  <building><instrumentRange>12</instrumentRange></building>
```

而原版 `Defs/Core/ThingDefs_Buildings/Buildings_MusicalInstruments.xml`：

```xml
<ThingDef Name="MusicalInstrumentBase" ParentName="BuildingBase" Abstract="True">
  <thingClass>Building_MusicalInstrument</thingClass>
  <tickerType>Normal</tickerType>
  <hasInteractionCell>true</hasInteractionCell>
  <comps>
    <li><compClass>CompQuality</compClass></li>
    <li><compClass>CompGatherSpot</compClass></li>        <!-- 聚集点 -->
    <li Class="CompProperties_ThrownFleckEmitter"><fleck>Music</fleck>
        <emissionInterval>100</emissionInterval></li>     <!-- 音符特效 -->
  </comps>
</ThingDef>
```

⇒ **我们的 5 件乐器已经是 `Building_MusicalInstrument`、已带 `CompGatherSpot`、已带音符 fleck、
已有 `instrumentRange`。** 我们**没有**覆盖 `<comps>`（0 次）⇒ 音符 fleck 仍然继承着。

### 1.5 ⚠️ 音效与音符都被 DLC 门槛卡住

`Source/RimWorld/Building_MusicalInstrument.cs`：

```csharp
public void StartPlaying(Pawn player)
{
    if (ModLister.CheckRoyaltyOrIdeology("Musical instrument"))   // ← 门槛
        currentPlayer = player;
}
protected override void Tick()
{
    base.Tick();
    if (currentPlayer != null) { 启动 soundPlaying }
    else { soundPlaying = null; }
    soundPlaying?.Maintain();
}
public override void ExposeData() { ... }     // currentPlayer 是 private，且有存档
```

- `StartPlaying` / `StopPlaying` **不是 virtual**，`currentPlayer` 是 **private**
  ⇒ **不能直接重写**
- `Tick()` 是 **protected override** ⇒ **可以**在这里自己维护播放状态
- 我们的音效字段：**5 件全是** `<soundPlayInstrument MayRequire="Ludeon.RimWorld.Royalty">Harp_Play</soundPlayInstrument>`
  ⇒ 没装 Royalty 时该字段为空 ⇒ 也没声音

**结论**：自办演唱会要"有声音 + 有音符"，**必须自己维护播放状态**，
不能依赖 `StartPlaying`（它被 DLC 门槛挡着，且作者本机虽装了全 DLC，
但 mod 的定位是"未装 DLC 自动降级"）。

`Dialog_BeginRitual` / `RitualRole` / `RitualRoleAssignments` / `RitualOutcomeEffectDef`
**全部属于 Ideology**。

- 直接引用 ⇒ 没装 Ideology 的玩家**加载即崩**（`TypeLoadException`）

**这是本设计里风险最高的一条，施工时必须在每个入口重复检查。**

## 2. 目标体验（玩家视角的完整流程）

```
① 玩家在殖民地建好一组合格乐器（≥1 麦克风 + ≥2 其它乐器，同一房间/同一片空地）
       ↓
② 点任意一件乐器 → gizmo「开演唱会」
       ↓
③ 弹出选人对话框（原版仪式那套外观）：
     左：候选殖民者列表（带技能、当前状态、不适合的原因）
     右：角色槽位 —— 主唱 / 键盘 / 鼓 / 吉他 / 贝斯 / 观众
       ↓
④ 点「开始」→ 演出开始
     · 乐手自动走到各自乐器操作点（JobDriver_BinguinPlayInstrument）
     · 主唱走到麦克风（JobDriver_BinguinBandWaitAtMic → 开演后演奏）
     · 观众找座位坐下（JobDriver_BinguinWatchConcert）
     · 音符 fleck + 演奏音效（自己维护播放状态）
     · 观众持续加 Recreation
       ↓
⑤ 4 小时后（或玩家手动停 / 主唱倒下）自动收尾：
     · 按技能算表演质量 → 四档之一
     · 观众 / 表演者各自的心情
     · 门票结算（复用 BinguinBandTicket）
     · 散场
```

## 4. 场地判定规则（第 1 部分）

### 4.1 什么叫"一组乐器"

照抄 `GatheringWorker_Concert.TryFindGatherSpot` 的思路：

```
遍历 map.listerBuildings.AllBuildingsColonistOfClass<Building_MusicalInstrument>()
  → 过滤：ValidateGatheringSpot(InteractionCell ...) && InstrumentAccessible(...)
  → 按 instrumentRange 分组，取 range 最大的那一组
```

**我们额外要做的**（原版没有的）：
- 原版只取**一个** spot（`spot = result.InteractionCell`）
- 我们要把**同一组的所有乐器**都收进来当"乐手位"
- 判定"同一组"：`距离 < range` 且**同一个 Room**（照抄 `Building_MusicalInstrument.IsAffectedByInstrument` 的 `GetRoom` 比较）

### 4.2 合格标准（不合格时按钮禁用 + 说明缺什么）

| 条件 | 说明 |
|---|---|
| ≥1 个**麦克风** | `Binguin_Band_Microphone`，主唱位 |
| ≥2 件**其它乐器** | 键盘/鼓/吉他/贝斯任选（2.4 决定：乐手可缺人，但**场地**至少要够像个演出） |
| 圈内**有地可站** | 至少主唱位 + 乐手位可达 |
| 圈内**有座位**（可选） | 没座位就退化成"站着看"（现有 `JobDriver_BinguinWatchConcert` 已支持 `targetA` 无效时原地看） |
| 不在演出中 | `!BinguinConcert.Active` |

### 4.3 场地信息预览（1.4）

在乐器上挂一个 gizmo「查看场地」或 ITab，显示：
- 这组乐器有几件、都是什么
- 圈内能坐多少人
- 缺什么（红字）

## 5. 发起流程（第 2 部分）

### 5.1 入口：乐器上的 gizmo

```csharp
// 伪代码
public override IEnumerable<Gizmo> GetGizmos()
{
    // base 的 gizmo 先给（原版乐器本来就有，但被 DLC 门槛挡着 —— 见风险）
    foreach (var g in base.GetGizmos()) yield return g;

    if (!ModsConfig.IdeologyActive) yield break;      // ★ 硬检查，没装就不显示
    if (Faction.OfPlayer == null) yield break;

    var venue = BinguinConcertVenue.FindFor(this);
    var gizmo = new Command_Action {
        defaultLabel = "开演唱会",
        defaultDesc  = venue != null
            ? "在这个场地办一场演唱会。"
            : "场地不合格：" + BinguinConcertVenue.WhyNot(this),
        icon = ...,
        action = () => BinguinConcertSetupDialog.Open(venue),
    };
    if (venue == null) gizmo.Disable("场地不合格");
    yield return gizmo;
}
```

  ⇒ 更干净，且子类正好用来**自己维护播放状态**

## 6. 演出流程（第 3 部分）

### 6.1 开始

```csharp
BinguinConcert.Start(venue, singer, musicians, audience);   // 扩展后的入口
  ├─ BinguinConcert.EndTick = 现在 + DurationTicks
  ├─ 派 job：
  │    主唱    → Binguin_PlayInBand（麦克风）    ← 或先 WaitAtMic
  │    乐手    → Binguin_PlayInBand（各自乐器）
  │    观众    → Binguin_WatchConcert（座位；无座位则原地）
  ├─ 自己维护每个乐器的"正在演奏"状态（见 6.3）
  ├─ 门票结算（BinguinBandTicket.SettleAtStart）
  └─ 弹消息"演唱会开始了"
```

**为什么不用 `LordMaker`**：Lord 适合"一群人自主行动 + 职责树"，
而我们的行为是**明确指派 person→instrument**。用 job 指派更直接可控。
（`LordJob_BinguinCrowd` 只用于外团来访那套。）

### 6.2 演出中

现有三个 JobDriver 的结束条件都是 `BinguinConcert.Active` ⇒ **到点自动收工**，
不需要我们额外驱动。

`BinguinConcertDirector.Tick()`（每 60 tick 一次足够）：

| 检查 | 处理 |
|---|---|
| 主唱 null / 死 / 未 spawned / 不在场地 | **终止演出**（走 6.4 收尾） |
| 某乐手失效 | 该乐器停奏，其余继续（演出不中止） |

| 有人被征召 | **一期不特殊处理**（6.1 延后）⇒ 他会自己中断 job |

### 6.3 音效与音符（第 7 项决定）

因为 `StartPlaying` 被 `CheckRoyaltyOrIdeology` 挡、且 `currentPlayer` 是 private：

```csharp
public class Building_BinguinBandInstrument : Building_MusicalInstrument
{
    private Pawn _player;                  // 自己的播放者
    private Sustainer _sound;

    public void BinguinStartPlaying(Pawn p) { _player = p; }
    public void BinguinStopPlaying() { _player = null; _sound = null; }
    public bool BinguinIsPlaying => _player != null;

    protected override void Tick()
    {
        base.Tick();                       // 保留原版行为（原版那条路径我们不依赖）
        if (_player == null) { _sound = null; return; }
        if (def.soundPlayInstrument != null && _sound == null)
            _sound = def.soundPlayInstrument.TrySpawnSustainer(
                SoundInfo.InMap(new TargetInfo(Position, Map), MaintenanceType.PerTick));
        _sound?.Maintain();
    }

    public override void ExposeData()
    {
        base.ExposeData();
        Scribe_References.Look(ref _player, "binguinBandPlayer");
    }
}
```

- **音符 fleck**：挂在 `CompProperties_ThrownFleckEmitter` 上，条件看的是原版
  `currentPlayer`（private）⇒ **我们自己的状态触发不了它**
  ⇒ 需要**自己在 `Tick()` 里手动 `FleckMaker.ThrowMetaIcon` / 或直接抛 `FleckDefOf.Music`**
- **音效**：`def.soundPlayInstrument` 现在全是 `MayRequire=Royalty` 的 `Harp_Play`
  ⇒ **建议改成不依赖 Royalty 的音频**，或给 5 件乐器各配不同的原版音效

> 我们要验证：`FleckMaker` 抛 `Music` fleck 的正确 API（施工第一步查 `FleckDef` 名和 `FleckMaker` 重载）

② 给【到场的】观众发心情（复用 BandVisitFlow.EndConcert 抽出后的具名方法）
③ 给表演者发心情（4.2）

## 11. 施工分期与验收

### 一期（本次）

按第 3.1 的 8 个新文件 + 第 3.2 的修改项，实现第 4~8 节。

**验收标准**（每一条都要实测，不能只看"编译过了"）：

1. 建好合格场地 → 乐器上出现「开演唱会」按钮
2. 场地不合格 → 按钮灰掉，说明缺什么

6. 演出中 → **有音符、有声音**、观众娱乐值上升
7. 4 小时后 → 自动收尾；**只给到场的人**发心情
8. 主唱中途死亡 → 演出中断、有提示、状态清干净
9. 中途存档 → 读档后状态正确恢复（或正确取消）
10. 与"乐队来访"事件不冲突
11. 全程 `Player.log` **无红字**
