# 编译方式（三种，随便挑一种）

> 冰鹅族 Binguin Race —— 2026-10-10 整理
> 以前只有 `build.ps1`（PowerShell），不习惯的人多，现在补上了 Visual Studio 和自动编译。

---

## 先选一种

| 方式 | 适合谁 | 需要装什么 |
|---|---|---|
| **① Visual Studio / Rider** | 想改 C# 代码的人 | VS 2022（社区版免费）或 Rider |
| **② 命令行 `dotnet build`** | 习惯命令行 / 用脚本 | .NET SDK 8+ |
| **③ `Source\build.ps1`** | **什么都不想装** | 不用装（Windows 自带 csc.exe） |

**三种方式结果完全一样**：都引用同一批 dll，最终都得到 `Assemblies\Binguin.dll`。
**互相不冲突**，今天用 VS、明天用 ps1 都没问题。

## ① Visual Studio / Rider（推荐）

1. 先 `git clone` 仓库（或用 GitHub Desktop）
2. 双击 **`Source\Binguin\Binguin.Race.sln`**
3. 菜单 **生成 → 生成解决方案**（快捷键 `Ctrl+Shift+B`）
4. 产物自动铺到 mod 根目录的 `Assemblies\Binguin.dll`

> 📁 **目录结构**（2026-10-10 起）：
> ```
> Source\
>   build.ps1                    ← 老的编译脚本（还能用）
>   Binguin\                     ← 工程和源码都在这
>     Binguin.Race.sln
>     Binguin.Race.csproj
>     *.cs                       ← 89 个源文件
>     bin\ obj\                  ← 编译中间产物（本地，.gitignore 挡掉）
> ```
> **改代码就去 `Source\Binguin\` 里改。**

> ✅ **编译完会自动铺到 mod 目录**（csproj 里的 `CopyToCustomDirectory`）：
> `Binguin.dll` → `Assemblies\`，`About.xml` → `About\`。
> 不用手动复制（要复制到**游戏**目录才需要另跑部署脚本）。

> ⚠️ **`Bin\OutputPath` 故意没设**（2026-10-10，协作者 CiÇo 要求）：
> 编译输出走默认的 `Source\Binguin\bin\Release\net48\`，**留在本地**；
> 让 mod 目录拿到 dll 靠的是「复制过去」，而不是把编译输出直接指向 mod 目录。
> 这样 `bin\` 里只有我们自己的文件，**一眼就能看出有没有多带游戏 dll**。
> 详见下面 FAQ「bin 里会不会混进 Unity 的 dll」。

### 游戏目录怎么指定

mod 必须引用游戏的 `Assembly-CSharp.dll` / `UnityEngine.*.dll` 才能编译，
而**每台电脑的游戏装在哪不一样**。csproj 会按这个顺序找：

**三种指定方式，任选一种**（2026-10-10 起 csproj 里**不再自动探测**了，
只有一行让你填 —— 协作者 CiÇo 说「猜九次不如直接填一次」）：

| 方式 | 怎么做 | 推荐度 |
|---|---|---|
| **① `Binguin.local.props`** | 复制 `Binguin.local.props.example` 成 `Binguin.local.props`，改里面的路径 | ★ **推荐**（不进 git，不会和别人的路径打架） |
| ② 命令行参数 | `dotnet build -p:RimWorldDir="D:\RimWorld"` | 临时用 |
| ③ 直接改 csproj | 改 `Source\Binguin\Binguin.Race.csproj` 里 `<RimWorldDir>` 那一行 | ⚠️ 记得**别提交** |

**怎么找自己的路径**：Steam → 库 → 右键 RimWorld → 管理 → **浏览本地文件**，
地址栏里那一串就是（例：`G:\SteamLibrary\steamapps\common\RimWorld`）。

**都没填会报一条清楚的错**（不是一堆看不懂的 CS0006）：

```
error BINGUIN001: 找不到 RimWorld 的 Managed 目录。三种指定方式，任选一种：
  1) 命令行（临时）： dotnet build -p:RimWorldDir="D:\RimWorld"
  2) 推荐：复制 Binguin.local.props.example 为 Binguin.local.props，把里面的路径改成你自己的
     （这个文件不进 git，改它不会和别人的路径打架）
  3) 或直接改 Binguin.Race.csproj 里 <RimWorldDir> 那一行（⚠️ 记得别提交）
  当前的值：[]
  需要的文件：\RimWorldWin64_Data\Managed\Assembly-CSharp.dll
```

> 💡 **为什么推荐方式 ①**：每台电脑的 RimWorld 装在哪都不一样。
> 如果大家都去改 csproj 那一行，`git status` 会一直是脏的，
> 手滑提交还会**覆盖别人的路径**。放进 `Binguin.local.props`（已被 `.gitignore` 挡掉）
> 就各改各的，永不冲突。

### 编译完自动部署（可选）

```powershell
dotnet build -p:DeployToGame=true
```

会把 `Binguin.dll` 自动复制到 `<RimWorld>\Mods\Binguin_Race_Mod\Assemblies\`。

或者在 VS 里加生成后事件（项目属性 → 生成事件）：

```
copy /Y "$(TargetDir)Binguin.dll" "G:\SteamLibrary\steamapps\common\RimWorld\Mods\Binguin_Race_Mod\Assemblies\"
```

## ② 命令行

```powershell
cd Source\Binguin
dotnet build                                   # 自动探测游戏目录
dotnet build -p:RimWorldDir="D:\RimWorld"      # 手动指定
dotnet build -c Release                        # Release（体积更小）
dotnet build -p:DeployToGame=true              # 编译 + 复制到游戏 Mods 目录
```

> ⚠️ **必须在 `Source\Binguin\` 里跑**（`.csproj` 在那儿）。
> 在别处跑 `dotnet build` 会报 `MSB1003: 未找到项目或解决方案文件`。

也可以从解决方案编（同一个目录）：

```powershell
cd Source\Binguin
dotnet build Binguin.Race.sln -c Release
```

## ③ 老办法：build.ps1（不用装任何东西）

> 注：`.cs` 源码现在都在 `Source\Binguin\` 子目录里，
> `build.ps1` 会**递归**去扫，你照常在 `Source\` 下运行即可。

```powershell
cd Source
.\build.ps1
```

或双击（会停在"按回车关闭"，不会一闪而过）。

指定游戏目录：

```powershell
.\build.ps1 -GameDir "D:\RimWorld"
```

> 💡 **`build.ps1` 自己仍会自动探测**（它跟 csproj 是两套独立的代码），
> 常见 Steam 位置它都能找到。**不填参数通常也能跑。**
> 探测不到再用 `-GameDir` 指定。

它靠 Windows 自带的 `csc.exe` 编译，**连 .NET SDK 都不需要**。
缺点是报错信息不如 VS 好看、没有自动补全。

...\RimWorld\Mods\Binguin_Race_Mod\Assemblies\Binguin.dll

## GitHub 上会自动编译

推代码 / 发 PR 时，GitHub 会自动跑一遍编译并校验产物
（配置在 `.github/workflows/build.yml`）。

- **绿色 ✓** = 编译通过
- **红色 ✗** = 编译失败，点进去能看到具体哪一行错了

它还会把编好的 `Binguin.dll` 存成 Artifact，可以直接在 Actions 页面下载
（不用自己装环境就能拿到 dll）。

> 那个工作流从 nuget.org 拉 `Krafs.Rimworld.Ref`（社区标准的 RimWorld 参考程序集包）
> 来获得游戏 dll —— 因为游戏 dll 有版权，**不能放进仓库**。
> **你自己电脑上编译不需要它**，直接用本地游戏就行。

## 常见问题

### Q：报 `CS0518: 预定义类型"IReadOnlyList`1"未定义或导入`

你八成把 `TargetFramework` 改成 `net40` 了。**别改，必须是 `net48`**。

原因写在 csproj 注释里：`IReadOnlyList<T>` 是 .NET 4.5 才有的，
net40 的官方参考程序集里没有它；而 Windows 上 .NET Framework 4.x 的**运行时**
mscorlib 里是有的（4.5/4.6/4.7/4.8 都是原地升级同一个目录）。
`build.ps1` 用的就是运行时 mscorlib，所以它一直没这问题。

### Q：报 `CS0246: 未能找到类型或命名空间名"HarmonyLib"`

Harmony 没还原上。跑一下：

```powershell
cd Source\Binguin
dotnet restore Binguin.Race.sln
```

Harmony 是通过 NuGet 包 `Lib.Harmony` 2.4.1 引的（与游戏里跑的版本一致）。

> ⚠️ **不要**改成从创意工坊目录用 `<HintPath>` 引 `0Harmony.dll` ——
> 实测（2026-10-09）那样在 `dotnet build` 下根本解析不到（正斜杠、反斜杠、
> 无条件引用都试过，全部 CS0246），NuGet 包一次就过。

### Q：编译成功但游戏里没变化

八成忘了部署。确认：

```
<游戏>\Mods\Binguin_Race_Mod\Assemblies\Binguin.dll
```

的时间戳是不是刚刚。不是就复制过去，然后**重启游戏**。

### Q：`obj/` `bin/` 要不要提交？

**不要**，`.gitignore` 已经挡掉了（`obj/` 和 `bin/`）。
这俩**本地留着就好** —— 是编译中间产物，删了下次编译会重新生成。

### Q：`bin\` 里会不会混进 Unity 的 dll？

**不会**（但这是**必须盯住**的点 —— 协作者 CiÇo 提醒过：
「output 如果不做剥离会带一堆 unity 自己的，那些必须去掉」）。

原理：
- 6 个游戏引用（`Assembly-CSharp` / `UnityEngine.*`）全都有 **`<Private>false</Private>`**
  ⇒ 编译要用，但**不复制进输出目录**
- Harmony 用 `PackageReference` + **`ExcludeAssets=runtime`** ⇒ 同样不复制

实测（强制清空 `bin\` 后完整重建）：

```
bin\Release\net48\ 里只有:  Binguin.dll   364 KB
```

csproj 里还加了一道**守卫**：`CopyToCustomDirectory` 会检查输出目录，
发现 `Unity*` / `0Harmony` / `mscorlib` / `System.*` 就报
`warning BINGUIN004`，防止以后有人给引用去掉了 `Private=false` 却没人发现。

> 🔧 **给新加引用的人**：如果你在 csproj 里加了 `<Reference>`，
> **记得带上 `<Private>false</Private>`**；加 `PackageReference` 就带
> `<ExcludeAssets>runtime</ExcludeAssets>`。否则游戏 dll 会跟着 mod 一起发出去。

### Q：`Assemblies\Binguin.dll` 要提交吗？

**要**。它是"clone 下来直接能玩"的前提 —— 别人拉到仓库就有 DLL，不用自己编译。

**但不用每次编译都提交**（作者 2026-10-10 原话：「不用每次都上传」）：

| 情况 | 提交 DLL？ |
|---|---|
| 改了 C# 代码、编译过了 | ✅ 要（否则别人拿到的是旧行为） |
| 只改 XML / 贴图 / 文案 | ❌ 不用（DLL 没变，提交只是噪音） |
| 反复调试、还没定稿 | ❌ 不用（等定稿一起提交） |
| 准备发版 / 让人测试 | ✅ **一定**（否则对方 clone 下来没 DLL，mod 加载不了） |

> ⚠️ **千万不要把它加进 `.gitignore`**。
> 曾经加过一次，结果：别人 clone 下来**没有 DLL ⇒ 所有 C# 功能都没有**，
> 表现成一堆莫名其妙的症状（比如「没有装配按钮」），很难查。已回滚。
> `.gitignore` 只挡 `Assemblies/*.pdb`。
>
> 📄 `Assemblies/README.md` 也写了这条（给直接点进那个目录的人看）。

## 改代码时的注意事项

| 事项 | 说明 |
|---|---|
| **语言版本是 C# 5** | 没有 `?.`、`$"插值"`、表达式体成员、`nameof`… 用了会编译错 |
| **目标框架别改** | 必须 `net48`（理由见上面 Q1） |
| **别用 4.5+ 才有的 API** | 编译能过但游戏里可能 `MissingMethodException`。不确定就用 `build.ps1` 编一遍对比（它更严格） |
| **XML 里别写本 Mod 的 C# 类型名** | 见 [铁规则.md](铁规则.md) |
| **不要改数值 / 玩法平衡** | 见 [铁规则.md](铁规则.md) |

## 三种方式的产物一样吗？

一样。实测对比（2026-10-10）：

```
排除编译器生成的闭包类后的真实类型数:  Roslyn(VS/dotnet)版 = 193，csc(ps1)版 = 193
只在一边有的类型:  0 个
>>> 真实类型集合完全相同
```

唯一差别是**编译器自动生成的闭包类命名方式**（Roslyn 用 `<>c__DisplayClass1_0`，
老 csc 用 `<>c__DisplayClass1`），对功能没有任何影响。
