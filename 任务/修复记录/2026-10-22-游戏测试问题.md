# 2026-10-22 游戏测试问题修复记录

本轮针对滑行免疫配置、外交官离场、乐队入场并发绘制、演唱会音乐和调试生成位置进行修改。目标版本为 RimWorld 1.7，没有恢复 1.6 或加入旧存档兼容层。全程未使用子代理。

工作区在本轮开始前已有上一轮 1.7 迁移、目录整理、翻译及构建部署修改。本记录仅列本轮增量；Git 原生审阅视图会同时包含之前尚未提交的改动。

## 1. 滑行免疫的 Hediff 配置红字

**原因已确认：** `Binguin_SlideImmunity` 带有 `HediffCompProperties_Disappears`，但没有声明能容纳 Comp 的 `hediffClass`。上一轮补入消失组件时遗漏了这个字段。

在 `Defs/Features/Sliding/ThingDefs_MiscAndUnfinished.xml` 为该 Def 补充：

```xml
<hediffClass>HediffWithComps</hediffClass>
```

保留消失组件、Def 身份和持续时间；没有改变滑行玩法数值。

## 2. 外交官寻路异常与未交谈就离场

**寻路原因已确认：** 进入殖民地和返回地图边缘的两处调用，把旧的 `TraverseMode.ByPawn` 参数传给了 1.7 的区域寻路参数位置。两处均改为 Pawn 的公开 `CanReach` 入口，由原版构造对应寻路参数。

**等待行为原因已确认：** 原先只派发一次 `Goto`，没有管理外交官的长期等待职责。该任务结束后，普通外派系 Pawn 的兜底 AI 会自行离场。

修改内容：

- 新增 `LordJob_BinguinDiplomat`，让未答复的外交官在殖民地等待点附近等待。
- 答复后的离场流程只释放本事件创建的等待 Lord，然后继续既有流程。
- 等待期间若没有 Lord，或已被普通离场 Lord 接管，定期看护会恢复等待职责；不夺取其他事件的队伍。
- 等待点额外检查可达性，选点失败时退回当前站立位置。
- 已有存活、在图的外交官时，重复调试派遣不再生成第二人。
- 新一轮派遣重置上一轮的答复、离场目标、计时及好感结算标志。

没有调整既有好感数值或停留时间。

## 3. 乐队入场时的并发集合异常

**已确认的边界：** 本地 1.7 的 `DynamicDrawManager` 先在主线程执行 `EnsureInitialized`，再通过作业并行执行 `ParallelPreDraw`。用户日志中的异常发生在这条并行调用链，但没有给出具体集合、实体或更深层调用位置。

检查了当前安装的 **1.7** ChezhouLib 绘制补丁。它的绘制上下文使用线程局部状态，场景实体状态使用 `ConditionalWeakTable`。日志列出该 Prefix/Finalizer，不能据此认定它就是集合损坏的来源。因此没有修改、禁用第三方 DLL，也没有隐藏异常。

新增 `Patch_BinguinMainThreadPreDraw`：

- 精确挂钩 `Thing.DynamicDrawPhase(DrawPhase)`。
- 对冰鹅族 Pawn，以及 Def 所属 packageId 为 `binguin.race` 的非 Pawn 实体，在主线程的初始化阶段完成同一预绘制阶段。
- 跳过这些实体随后在工作线程上重复执行的预绘制。
- 其他实体仍保留原版并行预绘制；没有修改全局单线程绘制设置。
- 复用现有 `SafePatch` 注册与失败日志。没有使用吞异常的 Finalizer。

**验收状态：兼容处理已实现并通过构建，实际组合复测待完成。** 当前证据不足以声称已找到第三方内部的具体冲突集合。该处理会将本模组实体的预绘制工作移到主线程，大规模实体场景的帧耗时尚未实测。

## 4. 演唱会没有切换歌曲

发现并处理了三处问题：

1. 来访乐队的开演入口原来只切换演出状态、结算门票，没有提交任何歌单。
2. 自办演出对同一首曲目同时调用背景音乐和一次性音效，可能产生重复播放。
3. 歌单按游戏 tick 换曲；倍速游戏会提前切断按真实时间播放的音频。

按本轮确认，来访乐队现在先打开原有选曲窗口，最多选择四首，确认后开始演出并结算门票。关闭窗口不开始演出；确认时重新检查主唱仍然在图且存活。

新增独立的 `BinguinConcertMusicPlayer`，来访乐队、自办演出和调试开演共用：

- 有可用 `SongDef` 时，只走原版背景音乐轨道。
- `ForcePlaySong` 的布尔参数使用 `false`，尊重玩家设置的音乐音量。
- 仅在背景音乐资源不可用时，才尝试 `SoundDef` 后备，并输出去重警告。
- 在 `GameComponentUpdate` 的主线程帧更新中推进，不再使用游戏 tick 作为背景音乐结束依据。
- 背景音乐根据音乐管理器的播放状态推进；音效后备按配置时长换算真实秒数。
- 歌单在散场后继续播完，保留原有要求。
- 当前曲目索引正常保存；读档后从该首开头继续，不承诺恢复音频的秒级播放位置。
- 缺少可播放音频或播放抛出异常时记录原因并跳过，避免每帧重复刷日志。

调试“立刻开始”优先走已经到场的自办预约或来访乐队入口；无现场演出时，仍可选歌测试演唱会状态和音乐。没有改动四小时演出时长。

## 5. 调试生成可以选择地图位置

- 三个钓竿测试物资菜单项改用 `DebugActionType.ToolMap`，点击地图选点后生成。
- 装配台的测试套件按钮也改为先选点；显示和回调均检查上帝模式及玩家所有权。
- 物资使用 `GenPlace.TryPlaceThing(..., ThingPlaceMode.Near)` 在所选位置附近放置，避免使用覆盖式生成。
- 乐队地标的调试生成支持地图选点，并复用场地完整空地检查；普通任务的自动选址入口不变。
- 新增按钮名称、说明和地标放置失败提示的中英文翻译，共三对键。

## 8. 游戏内复测顺序

1. 使用更新后的开发版本重新启动游戏，确认不再出现 `Binguin_SlideImmunity` 的配置错误。
2. 调试派遣外交官，观察她走进殖民地并保持等待；重复派遣不应生成第二人。交谈并答复后检查既有离场和好感结算。
3. 调试菜单选择测试套件，在两处不同位置点击生成；确认物资在点击处附近，原有物品没有消失。装配台按钮应在上帝模式下可用。
4. 在空地点击生成地标，一键建完场地并让乐队入场，保留原来的 ChezhouLib/HAR 等组合，检查并发绘制错误是否再现。
5. 右键主唱，先关闭选曲窗口，确认未开演；再次交互选择两至四首并确认，检查第一首替换背景音乐、后续曲目按顺序播放。
6. 在倍速及散场后继续观察歌单，确认曲目不会因游戏 tick 加速而提前切换。音乐音量由原版设置控制。
7. 若并发错误仍出现，保留从第一条异常开始的完整 Player.log；下一步需要实体身份或更深层堆栈，才能把兼容处理收敛到具体冲突位置。


## 9. 后续修复：批处理窗口停留与重复部署失败

上文记录的是此前修复结束时的状态。本次用户要求直接运行部署入口，已执行并完成实际游戏目录部署；该状态更新不代表完成了游戏内加载或玩法复测。

**已复现的原因：** `deploy_modSelf.bat` 使用 Windows PowerShell 5.1。读取旧 `binguin-files.json` 时，`@(Get-Content ... | ConvertFrom-Json)` 会把 JSON 文件列表包成嵌套数组，随后 `Join-Path` 把整份列表当作一个文件名而失败。因此空目标首次部署能成功，已有清单的更新部署失败。

本次修改范围：

- `package_modSelf.ps1`：直接接收反序列化结果再逐项遍历，拒绝无效清单项；校验旧清单后再构建、清理和复制。
- `compile_modSelf.bat`、`deploy_modSelf.bat`：成功和失败均无条件暂停，显示结果与真实退出码，按键后才结束；先切换到项目目录，执行后恢复调用者目录。批处理使用标准 CRLF 换行，无个人路径。
- 编译批处理增加可选的第二参数用于产物输出目录，支持中文及空格；默认仍为 Release。
- `Source/BUILDING.md`：补充暂停行为、输出目录参数，以及自动化直接调用 PowerShell 脚本的说明。

实际验证：

| 入口与场景 | 按键前 | 按键后退出码 |
| --- | --- | ---: |
| 编译成功，项目外工作目录、中文空格输出路径 | 显示成功并等待按键 | 0 |
| 编译参数无效 | 保留原始错误、显示失败并等待按键 | 1 |
| 默认部署到自动识别的游戏目录，目标已有清单 | 完整部署成功并等待按键 | 0 |
| 部署目标错误地指定为开发目录 | 拒绝写入、显示失败并等待按键 | 1 |

部署目标为自动识别的 RimWorld 安装下的 `Mods/Binguin`；执行前未检测到游戏进程。部署清单中的 **224 个文件**已逐一比较 SHA-256，全部与开发目录对应文件一致，程序集目录中只有本模组 `Binguin.dll`。未修改玩法源码或 XML，未新增项目 Tools 文件，未暂存或提交 Git 改动。
